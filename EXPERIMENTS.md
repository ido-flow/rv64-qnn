## E1 — B0 baseline: INT8 dot product on RV64IMC

**Date** 2026-09-22 · **Reproduce** `./scripts/run_b0.sh` · **Raw** `results/b0.txt`

Setup: `riscv-none-elf-gcc 15.2.0`, `-march=rv64imc_zicsr_zifencei -mabi=lp64
-mcmodel=medany -O2`, bare-metal, Spike (commit `1960943`).
Kernel: `int32 acc += (a[k] - za) * w[k]`, K = 192, measured over `dot_b0` only.

### Correctness
numpy host reference = **96128**; bare-metal on Spike = **96128**. **MATCH.**

### Dynamic instruction count
`minstret` bracket across the call: **1548** instructions for **192** MACs
= **8.06 instructions / MAC**.
Static disassembly shows 8 instructions in the loop body; 1536 + 12 of call
overhead = 1548. Static and dynamic agree.

### Instruction mix (PC-filtered to `dot_b0`, 1541 instructions)

| class | count | share |
|---|---:|---:|
| int ALU | 772 | 50.1% |
| load | 384 | 24.9% |
| branch | 193 | 12.5% |
| **multiply** | **192** | **12.5%** |

**MACs per retired instruction: 0.125.**

### Code size
text 2916 B · data 16 B · bss 416 B. Zero floating-point instructions emitted.

### Bottlenecks identified (brief §2B requires three)

1. **Address generation — 50% of instructions.** Two `addi` pointer bumps and a
   zero-point `subw` per MAC. → post-increment load/store; hoist the zero point.
2. **Load overhead — 25%.** Two loads per MAC, each moving **one byte** through a
   64-bit datapath: 87.5% of the load path is wasted. → packed loads, which is
   what makes `xqmac8` possible at all.
3. **Loop control — 12.5%.** One branch per MAC. → hardware loops.

Only **12.5%** of retired instructions are the multiply that does the work.

### Methodology note — trace the region, not the program

A whole-program trace reports ~50% branch / ~49% load and is **meaningless**:
`syscalls.c` emits output over HTIF by writing a magic address and spinning on a
poll loop, which dominates the trace. All mixes must be PC-filtered to the kernel
symbol (`scripts/instr_mix.py --range LO HI`). Budget for this when profiling
full inference.

## E2 — Requantize semantics reverse-engineered from the .tflite

**Date** 2026-09-22 · **Reproduce** `scripts/ref_sweep.py` (all GEMM ops), `scripts/ref_conv.py` (one conv, annotated)

Method: run the model interpreter **without the XNNPACK delegate** with all
tensors preserved, dump every CONV_2D / FULLY_CONNECTED op's exact input,
weights, bias, output and quantization params, and reproduce each op in numpy
(im2col int32 GEMM + integer requantize), iterating on candidate rounding
rules until bit-exact.

Findings:

1. **Convs: single-round.** `clamp(RDBPOT(acc·M0, 31+rs) + zp)` matches all 20
   convs, 2,183,168 outputs, 0 mismatches. The textbook two-step gemmlowp
   (SRDHM then RDBPOT) is off by +1 on 0.065% — double-rounding artifact.
2. **FC: different backend, different rounding.** ruy semantics
   (trunc-SRDHM, then round-half-up shift) needed for 0/1000 mismatches.
   TFLite is internally inconsistent between kernels.
3. Rounding mode of the Q31 multiplier itself (ties-even vs ties-away) never
   mattered — no channel lands on a tie in this model.
4. Quantized PAD must fill with the **zero point** (−14 at input), not 0.
5. Weight zero-points are all 0 (symmetric); scales per output channel;
   weight layout `[Cout, kh, kw, Cin]`.

**Decision:** `xrq` implements the conv semantics only. One rounding stage in
hardware; FC deviates ≤ ±1 on ≤3/1000 logits vs TFLite (argmax unaffected).
`ref_conv.py` is the project golden reference from here on.

Also this session: preprocessing confirmed (torchvision ImageNet), smoke test
top-1 = "military uniform" on grace_hopper.jpg via the no-delegate interpreter.

## E4 — B1: software-optimized kernel (same ISA)

**Date** 2026-10-03 · **Reproduce** `make run-conv` (runs B0 and B1 back-to-back)

4-channel output tiling (one window load feeds four accumulators) + 8-way
unroll. Same arithmetic, same ISA, bit-exact.

| kernel | instr | instr/MAC | vs B0 |
|---|---:|---:|---:|
| B0 naive | 824,959,988 | 7.13 | 1.00x |
| **B1 tile4+unroll8** | **413,848,076** | **3.57** | **1.99x** |

This is the software ceiling on the stock ISA (further tiling yields
diminishing returns vs register pressure: 31 GPRs). X1's gain is measured
against THIS line, per brief §4's B1 row — the ISA must beat the compiler's
best, not the naive straw man.

## E6 — xrq: the second required instruction + verification suite

**Date** 2026-10-15 · **Reproduce** `make run-test && make run-conv` (Spike patch: `src/spike/`)

`xrq rd, rs1, rs2`: int32 accumulator in rs1; M0/shift/zero-point packed per
channel into one 64-bit rs2 word (prepared offline, `L_RQ[]`). Single-round E2
semantics. Design note: the original CSR-parameter plan was CORRECTED — the
kernels loop pixel-outermost (window reuse), so CSR writes would fire per
output; rs2-packing keeps the 2-read/1-write option-D shape and handles
per-channel naturally (DESIGN.md §4.2).

**Verification (brief §5 functional):** `src/spike/isa_test.c` — directed
corners + 20,000 randomized vectors per instruction vs independent C
references: **40,144 vectors, 0 failures.**

| kernel | instr | instr/MAC | step | cumulative |
|---|---:|---:|---:|---:|
| X1 xqdot8 | 75,926,769 | 0.657 | — | 10.86x |
| **X2 + xrq** | **73,267,673** | **0.634** | **1.036x** | **11.26x** |

The +3.6% is small BY STRUCTURE: requantize runs once per output element
(200,704) vs 14.45M xqdot8 ops — Amdahl's law measured, per the incremental-
evaluation rule. xrq's second effect — removing 2 data-dependent branches per
output — is invisible to instruction counts and is a predicted CYCLE win to
confirm on Wally RTL.

**Utilization (metric #7), measured exact:** XQDOT8 count = 258,048 = row MACs/8
